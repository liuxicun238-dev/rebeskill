# ChatGPT 网页聊天与生图桥接

该功能启动系统安装的 Google Chrome（找不到时使用 Microsoft Edge）操作 ChatGPT 网页，并在本机提供 OpenAI Chat/Images 兼容接口。它不使用 Electron 内置浏览器，不是 OpenAI 官方 API，也不会读取、导出或转发网页登录 Token/Cookie。

## 使用方法

1. 打开“设置 → 帮助”。
2. 在“ChatGPT 网页桥接”中点击“1. 打开普通 Chrome 登录”。这个登录窗口不带远程调试或自动化参数。
3. 在系统 Chrome/Edge 中登录自己的 ChatGPT 账号；登录成功后，关闭整个专用 Chrome/Edge 窗口。
4. 返回设置，点击“2. 登录完成后检查”。灵犀此时才用同一份专用浏览器资料进入自动化模式。
5. 点击“添加网页版聊天模型”，模型列表会新增“ChatGPT 网页版（本地 Chrome）”。
6. 如需生图，再点击“一键添加为生图模型”，并在“模型能力调度”的“文生图 / 图生图”中调整优先级。

本地接口默认为：

```text
http://127.0.0.1:3217/v1/chat/completions
http://127.0.0.1:3217/v1/images/generations
```

接口仅监听 `127.0.0.1`，写请求需要灵犀自动生成的本地密钥，并且同一时间只执行一个网页任务。每个灵犀聊天任务绑定独立的 ChatGPT 标签页和网页对话；连续消息直接在原对话中发送，不再每轮新建 ChatGPT 对话。灵犀历史发生压缩或整理时，也会在原网页对话中发送一次“以当前完整历史为准”的同步消息，不会因此新建对话。只有首次使用、任务切换、标签页被关闭或程序重启后映射丢失时才会创建新的网页对话。网页登录资料保存在灵犀专用的 Chrome 用户目录中，不会覆盖默认 Chrome 用户资料。

网页版聊天模型支持文本、多轮历史、SSE 兼容返回、ChatGPT 网页自身可用的搜索和分析能力，以及灵犀受控工具调用。网页模型只能用严格 JSON 协议“提出”白名单内的工具请求，桥接层不会执行网页文本；请求转换为标准 `tool_calls` 后，仍由灵犀原有的参数校验、授权和工具执行链处理，再把结果送回同一个网页对话。网页把协议包进代码块、插入 Copy code / json 标签、或把 JSON 拆成多行时，桥接层会尽量还原后再校验。真正损坏的 JSON、夹杂解释文字、未知工具或非对象参数仍会被拒绝。

## 常见情况

- 提示“需要登录”：重新执行第 1 步，在普通浏览器中完成登录，关闭整个专用浏览器窗口，再执行第 2 步。
- 提示“登录浏览器仍在打开”：不要只关闭标签页，需要关闭第 1 步打开的整个专用浏览器窗口。
- 出现验证码或安全检查：必须由用户在外部浏览器中手动完成。
- 长时间没有返回：查看外部浏览器中的 ChatGPT 页面是否报错，或是否仍在生成。
- 找不到浏览器：安装 Google Chrome 或 Microsoft Edge 后重试。
- 页面改版后无法找到输入框或图片：网页选择器需要随 ChatGPT 页面更新。
- 端口被占用：关闭占用 `3217` 端口的程序后重启灵犀。
- 提示 `INVALID_TOOL_CALL_PROTOCOL` / “灵犀工具调用不是有效 JSON”：先重启灵犀后再试。若外部 Chrome 里的 ChatGPT 回复夹杂了代码块按钮、解释文字，或 JSON 本身写坏，桥接层会拒绝执行；重新发送同一条任务即可。真正损坏的协议不会自动执行。

该适配层只适合个人本机、低并发使用。若需要稳定的生产服务，应使用 OpenAI 官方 Responses/Chat Completions/Images API。
